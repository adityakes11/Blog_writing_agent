# Inkline — Research-First AI Blog Studio

Inkline is a production-minded AI writing system that turns a topic into a research-backed, publishable blog. It combines a polished web interface with a typed LangGraph workflow, local Ollama inference, optional Tavily research, external image sourcing, and end-to-end LangSmith observability.

This project is designed to demonstrate how an AI engineer builds a reliable product around an LLM—not just a prompt.

<p align="center">
  <strong>Research → Plan → Draft → Validate → Publish</strong>
</p>

## Why this project stands out

Most blog generators hide the reasoning behind a single opaque model call. Inkline exposes and structures the important parts of the workflow:

- **Research-aware routing** decides whether a topic is evergreen, hybrid, or time-sensitive.
- **Evidence is first-class data** with normalized URLs, snippets, dates, deduplication, and citation constraints.
- **Structured planning** uses Pydantic models instead of relying on unvalidated free-form output.
- **Parallel section drafting** decomposes the article into tasks before writing.
- **Grounded generation rules** restrict current-event claims to the supplied evidence.
- **Observable execution** can be traced in LangSmith so successful runs and failures are visible.
- **Production-style delivery** separates the FastAPI API from the browser presentation layer.

## Engineering highlights

### 1. Typed stateful orchestration

The LangGraph state is explicitly modeled with `TypedDict`, Pydantic schemas, and typed evidence objects. Plans, tasks, router decisions, and evidence packs have predictable contracts.

### 2. Research routing

The router classifies the topic into:

- `closed_book` — evergreen content that does not need current web evidence
- `hybrid` — evergreen content with current examples, tools, or models
- `open_book` — volatile topics such as news, policy, pricing, or recent events

The selected mode controls recency windows, search behavior, planning constraints, and citation requirements.

### 3. Evidence-grounded writing

Research results are normalized and deduplicated before planning. The drafting prompt receives only the approved evidence URLs. For open-book content, unsupported specific claims are explicitly rejected instead of being silently invented.

### 4. Fan-out/fan-in generation

The planner creates focused writing tasks. LangGraph fans those tasks out to section workers, then the reducer restores task order and produces one coherent Markdown article. This makes the workflow easier to extend, inspect, and test than a single oversized generation prompt.

### 5. Responsible image handling

Images are not generated by an LLM. When the user opts in, Inkline adds a cover image from Unsplash through its search API or a deterministic external fallback URL. This keeps imagery separate from article reasoning and avoids unnecessary image-model cost.

### 6. Observability

LangSmith tracing can be enabled with environment variables. The trace dashboard provides a run-level view of:

- successful and failed traces
- execution timing
- router, research, planning, worker, and reducer calls
- model interactions and structured-output boundaries
- failure locations for debugging

The attached trace screenshot demonstrates the intended observability workflow: a successful run appears in the trace count with no corresponding error spike.

## Run locally

### Prerequisites

- Python 3.10+
- [Ollama](https://ollama.com/)
- A compatible local chat model
- Optional Tavily API key for live research
- Optional LangSmith API key for traces
- Optional Unsplash access key for image search

### Install

```powershell
git clone https://github.com/adityakes11/Blog_writing_agent.git
cd Blog_writing_agent
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
copy .env.example .env
```

### Prepare Ollama

In a separate terminal:

```powershell
ollama serve
ollama pull qwen2.5:3b
```

### Configure `.env`

```env
OLLAMA_MODEL=qwen2.5:3b
OLLAMA_BASE_URL=http://127.0.0.1:11434

TAVILY_API_KEY=your_tavily_api_key

LANGCHAIN_TRACING_V2=true
LANGCHAIN_ENDPOINT=https://api.smith.langchain.com
LANGCHAIN_API_KEY=your_langsmith_api_key
LANGCHAIN_PROJECT=inkline-blog-studio

UNSPLASH_ACCESS_KEY=your_unsplash_access_key
```

All provider keys are optional at development time. Without Tavily, evergreen generation still works but live source results may be empty. Without LangSmith, the app still runs but traces are not sent. Never commit `.env`.

### Start the application

```powershell
.\.venv\Scripts\python.exe -m uvicorn web_app:app --reload --host 127.0.0.1 --port 8000
```

Open <http://127.0.0.1:8000>.

Verify the API:

```powershell
curl http://127.0.0.1:8000/api/health
```

Expected:

```json
{"status":"ok","service":"blog-writing-agent"}
```

If port 8000 is busy:

```powershell
.\.venv\Scripts\python.exe -m uvicorn web_app:app --reload --host 127.0.0.1 --port 8001
```

## Observability with LangSmith

1. Create a LangSmith account and API key.
2. Add the following to `.env`:

   ```env
   LANGCHAIN_TRACING_V2=true
   LANGCHAIN_ENDPOINT=https://api.smith.langchain.com
   LANGCHAIN_API_KEY=your_langsmith_api_key
   LANGCHAIN_PROJECT=inkline-blog-studio
   ```

3. Restart the application.
4. Generate a blog.
5. Open the `inkline-blog-studio` project in LangSmith.
6. Inspect the trace tree, latency, model calls, and any errors.

Tracing is especially useful here because the workflow contains multiple meaningful stages rather than one black-box request.

## API

### `GET /api/health`

Returns service liveness:

```json
{"status":"ok","service":"blog-writing-agent"}
```

### `POST /api/generate`

Example request:

```json
{
  "topic": "How AI is changing developer productivity in 2026",
  "audience": "engineering leaders",
  "tone": "clear and insightful",
  "as_of": "2026-10-03",
  "include_images": true,
  "image_query": "AI developer workflow"
}
```

The response contains:

- `title`
- `final_markdown`
- `plan`
- `evidence`
- `research`
- `include_images`

## Security and reliability notes

- Keep `.env` and all provider keys out of Git.
- Review source links before publishing generated claims.
- Do not expose an unauthenticated Ollama endpoint to the internet.
- Restrict CORS origins before exposing the API publicly.
- External image URLs may be unavailable or rate-limited; article generation does not depend on them.
- Generated Markdown is written locally for convenience; add durable storage before building a multi-user publishing product.
